# Reporch CLI 1.0 beta gate

Each `1.0.0-rc.*` release starts its stability window only after the release
workflow has downloaded and exercised the published GitHub and npm artifacts on
all five supported target environments. The workflow then creates one GitHub
issue named `Reporch CLI <version> — 30-day stability window`.

The issue creation time is the authoritative start. It may be closed only when
all of the following remain true for 30 complete days:

- no critical security incident;
- no authoring data loss or unrecoverable migration failure;
- no duplicate publication or quota settlement;
- scheduled fuzz and source CI remain green;
- production Studio capabilities, validation, review, and publication remain
  compatible with the RC contract;
- every reported release-blocking defect is resolved and its regression test is
  linked from the issue.

The release workflow refuses the exact stable version `1.0.0` unless the most
recent RC issue is closed and at least 30 days elapsed between its creation and
closure. Shipping a newer RC therefore starts a new authoritative window. RCs
are published under npm `next` and as GitHub prereleases, so none can replace
the stable `latest` channel.
